## Что проверено и как
- **По исходному коду официальных SDK** (PyPI: `polymarket-client` 0.11.0 и `py-clob-client-v2` 1.1.0):
  - эндпоинты и HTTP-методы;
  - формат ордера V2 и post-only (только GTC/GTD);
  - батч ≤ 15;
  - сетка тиков и правила округления;
  - минимальный срок GTD 180 с;
  - формула комиссии `C·r·(p(1−p))^e` и где читать её параметры (`/clob-markets/{cid}` → `fd.r`, `fd.e`);
  - поля Gamma (`secondsDelay`, `feeSchedule`, `rewardsMaxSpread`, `gameStartTime`, `sportsMarketType`);
  - протоколы market, user и sports WS, их heartbeat;
  - статусы ордеров и сделок;
  - адреса контрактов;
  - session keys.
- **По официальному репозиторию Polymarket** (`agent-skills`): в спорте лимитки снимаются на старте, маркетабельные ордера ждут задержку около 3 с; heartbeat — 10 с; коды ошибок.
- **Не проверено напрямую.** docs.polymarket.com и API недоступны из этого окружения (egress 403). Всё, что взято через поисковую выдачу или вторичные источники, помечено [DOC?]/[2nd] и вынесено в чек-лист `api_notes.md` §16 для сверки на M1 с VPS.

## Главные выводы
1. **Поведение спорта** Polymarket (авто-отмена на старте, задержка тейкеров ~3 с, dead-man heartbeat) делает прематч-ММ управляемым. В лайве задержка тейкеров даёт мейкеру окно на отмену, но только при быстром фиде счёта.
2. **Источник коэффициентов.** The Odds API как основной источник для тенниса не подходит: не покрывает Challenger и ITF, прематч отдаёт с задержкой до 2 мин. Публичный API Pinnacle закрыт. Основной — Betfair Stream (если доступен по юрисдикции) или WS-агрегатор с Pinnacle и Betfair.
3. **Правила тенниса** на polymarket.com (walkover → 50-50, снятие → проходящий) отличаются от правил части букмекеров. Нужен модуль `rules_adjust`.
4. **Цель $10k за 3–4 месяца** при гейтах маловероятна (≤ ~20%): полный капитал появляется примерно на 13-й неделе. Реалистично — 6–9 месяцев при капитале $10–20k и net edge ≥ 0.5% от оборота. Подробности — `docs/capacity.md`.
