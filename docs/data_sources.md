### Вывод по коэффициентам

1. The Odds API как **единственный** источник не годится для тенниса:
   - не покрывает большую часть матчей, которые листит Polymarket (Challenger, ITF, WTA 125, часть ATP/WTA 250);
   - задержка прематча до 2 минут несовместима с `stale_ms` около 30 с из промта.
2. Рекомендация:
   - если Betfair Exchange доступен по юрисдикции — основной источник **Betfair Stream**, а OddsPapi или The Odds API — для сверки консенсуса и CLV;
   - если нет — **OddsPapi (WS)** как основной и The Odds API для сверки на крупных событиях.
3. В интерфейсе `OddsProvider` у каждой котировки есть поля `source`, `bookmaker`, `ts_source` (время у источника, если отдают) и `ts_recv`. Устаревание считаем по `ts_recv` с поправкой на известный лаг источника.

### Почему задержка фида решает всё в лайве

В спорте маркетабельный ордер ждёт около 3 с, прежде чем сматчиться (`secondsDelay`, см. `docs/api_notes.md`, §12). После очка происходит следующее:
- быстрый тейкер отправляет ордер, но тот ждёт ~3 с;
- если наш путь «очко → событие в фиде → отмена подтверждена» укладывается примерно в `3 с − (задержка фида тейкера)`, мы успеваем снять котировку;
- если наш фид отстаёт на 5–15 с (типично для дешёвых фидов), каждое важное очко нас «выносит».

Отсюда правило из промта (§6.3): p95 задержки «событие → отмена подтверждена» — **гейт** для лайва. Порог — `secondsDelay` минус запас, по умолчанию ≤ 1.5 с. Если p95 выше, лайв-ММ по этому источнику выключается автоматически.

Правило бюджета: пока edge не доказан на Live-S, данные стоят не больше $200/мес. Дорогой фид берём только тогда, когда замеры показывают, что лайв окупит его при текущей ёмкости.

## 4. Методика замера задержки (M1/M7)

1. Для каждого сообщения фида логируем `ts_recv`: `time.time_ns()` при чтении из сокета на VPS с синхронизированными часами (chrony; дрейф мониторит `core/clock.py`).
2. **Счёт.** Сопоставляем одно и то же очко в нескольких фидах и в Sports WS: у кого оно раньше, насколько и с каким p50/p95. Для абсолютной оценки берём скачки книги Polymarket, то есть серии `last_trade_price` и `price_change`: рынок реагирует на очко раньше медленных фидов.
3. **Коэффициенты.** Время движения линии Pinnacle или Betfair против времени движения мида Polymarket (lead-lag, кросс-корреляция приращений). Если Polymarket систематически двигается раньше нашего фида, у нас нет информационного преимущества, и спред нужно расширять.
4. Результат — таблица `feed × метрика (p50/p95/p99, доля пропусков, доля противоречий)` в ежедневном отчёте.
