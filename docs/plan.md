Каждая веха заканчивается рабочим кодом, тестами и коротким отчётом в `docs/reports/Mx.md`: что сделано, что проверено, открытые вопросы. Реальные ордера до Live-S запрещены. Для Live-S нужны `LIVE_TRADING=true` и ваше подтверждение в чате.

Сроки — ориентир для одного разработчика (я + ваши ревью). Рекордер работает непрерывно с M1.
Пока идут первые 7 дней записи, делаем только то, что не является стратегией: M2 (сопоставление и правила) и разбор данных. Pricing, котировщик и остальной код стратегии — после отчёта M1 (решение пользователя).

## M1 — Рекордер данных и замеры (код готов; дальше 7 дней записи на VPS в Ереване)

**Решение пользователя (2026-09-25):** M1 начинается с рекордера. Пишем книги спортивных рынков Polymarket, Sports WS Polymarket и OddsPapi (free/trial) в Parquet. Через 7 дней записи — отчёт. **Код стратегии до отчёта не пишется.**

**Сделано в коде** (`src/polybot`, подробности — `docs/reports/M1.md`):
- каркас: `pyproject` (Python 3.12, закреплённые версии), `ruff`, `mypy --strict` на весь пакет, `pytest` + `hypothesis`, structlog с маскировкой секретов, pydantic-settings, `config/*.yaml`, Dockerfile и compose, `Makefile`;
- **geoblock-гейт**: рекордер не стартует, если ответ не «разрешено» (`blocked == false` и страна из `allowed_countries`, для VPS — `AM`); проверка повторяется раз в 10 мин;
- рекордер: discovery через Gamma (теннис, футбол, баскетбол), пул WS market channel (≤ 200 активов на соединение, PING/PONG, реконнект, ресинк), Sports WS, сверка книг с REST, `/clob-markets`, награды, непрерывный замер RTT, Parquet (`date=/source=`, zstd);
- OddsPapi: клиент с постоянным бюджетом запросов, режимы `paid_rest` и `ws` (включаются конфигом после выбора тарифа), `polybot oddspapi-eval` — проверка по плану `docs/data_sources.md` §6;
- инструменты VPS: `polybot netcheck` (блокировки у провайдера или регулятора), `polybot latency` (p50/p95 до CLOB и WS), `polybot discover` (теги и типы рынков по видам спорта);
- сопоставление v0: рынок Polymarket ↔ матч OddsPapi (точный ключ Betradar → fuzzy с отказом при неоднозначности). Нужно для отчёта о точности;
- `polybot report` — отчёт по записанной неделе.

**Сделать на VPS (вы + я по результатам):**
1. Развернуть по `docs/runbook_m1.md`: `polybot geocheck`, `polybot netcheck`, `polybot latency` → результаты в `docs/latency.md`.
2. `polybot discover` → проверить и при необходимости поправить в `config/recorder.yaml` значения `sportsMarketType` для футбола и баскетбола.
3. Запустить рекордер на 7 дней. OddsPapi — шаги `oddspapi-eval` в дни 1, 4 и 7 (план — `docs/data_sources.md` §6).
4. Через 7 дней: `polybot report` → отчёт `docs/reports/M1.md` (часть 2).

**Отчёт через 7 дней (приёмка M1):**
- реальные объёмы по видам спорта и по времени до старта;
- спреды;
- задержки фидов (Sports WS против реакции книги, OddsPapi) и сети (REST, WS);

- ранние старты в теннисе и момент авто-отмены биржей;
- таблица проверки OddsPapi (`docs/data_sources.md` §6) и решение по тарифу в рамках $200/мес.

**Технические критерии записи:**
- рекордер работает 7 дней; перезапуски и дыры видны в отчёте (служебные записи `connected`/`disconnected`);

## M2 — Сопоставление событий и правил (≈ 1 неделя)
**Сделать:**
- `event_matcher.py`: v0 уже есть в M1 (Betradar id → fuzzy по участникам и времени, отказ при неоднозначности). В M2 — турнир и лига, YAML-оверрайды, парный разряд, разметка по отчёту M1;
- `rules_parser.py`: классы правил тенниса и футбола из `description`, флаги риска; незнакомый текст → `INELIGIBLE`;
- отчёт точности на всех записанных рынках за 1–2 недели.

**Приёмка:** на ручной разметке ≥ 200 рынков точность ≥ 99.5% среди принятых, ложных совпадений 0; доля принятых рынков указывается в отчёте.

## M3 — Pricing (≈ 1–1.5 недели)
**Сделать:**
- `devig.py`: multiplicative, power, Shin; консенсус с весами и `confidence`;
- `rules_adjust.py`;
- `stale_ms(τ)`;
- `tennis_markov.py`: DP, форматы турниров;
- `tennis_calib.py`: калибровка, Beta-байес.

**Приёмка:**
- unit- и property-тесты (hypothesis): сумма вероятностей = 1, диапазон [0, 1], симметрия, монотонность по счёту, сверка с Монте-Карло;
- сравнение fair с серединой книги Polymarket на записанных данных: распределение отклонений по турам и времени до старта.

## M4 — Котировщик, OMS, риск, paper (≈ 2 недели)
**Сделать:**
- `quoter.py`, `inventory.py`, `scheduler.py` (FSM), `selector.py`;
- **защита от раннего старта в `scheduler.py`** (решение 5, `docs/architecture.md` §6): снимаем котировки при **любом** из условий — фид показывает «in progress», завершился предыдущий матч на том же корте (или, пока нет данных о кортах, любой матч того же турнира), наступило `T − pull_before_start_s`. Авто-отмена биржи — только дополнительный слой;
- `order_manager.py`: дифф, батчи ≤ 15, идемпотентность, `rate_budget`, режимы `DEGRADED`;
- `heartbeat.py`;
- `risk/*`: лимиты, kill-switch, reconciler;
- `paper.py`: очередь по L2, частичные исполнения;
- Telegram: `/status`, `/pnl`, `/pause`, `/resume`, `/killall`.

**Приёмка:**
- сквозной paper-цикл 48 часов без крэшей;
- тесты `scheduler`: каждое из трёх условий раннего старта по отдельности переводит рынок в `PRE_START_PULL`; реплей записанных ранних стартов из M1 не оставляет котировок после фактического старта;
- хаос-тесты: обрыв WS, 425/503/429/5xx, задержка фида, частичное исполнение, рестарт посреди позиции;
- при каждом старте и остановке выполняется `cancel_all`.

## M5 — Бэктест-реплей (≈ 1–1.5 недели; нужно ≥ 3–4 недель записи)
**Сделать:** `replay.py` через тот же код стратегии и OMS; `fill_model.py` (FIFO по L2, латентность, delay-фаза тейкеров); отчёты по markout, CLV и разложению PnL; чувствительность к ±параметрам; кривая ёмкости.

**Приёмка, гейт «Backtest»:** markout ≥ 0 и PnL после комиссий > 0 на out-of-sample неделях; устойчивость к ±25% по γ, k, `min_edge` и `requote_threshold`.

## M6 — Paper + Shadow → Live-S (прематч: теннис, футбол, баскетбол) (≈ 1.5 недели + 2 недели Live-S)

### Открытые вопросы после решений
- **Тариф OddsPapi.** Бесплатных 250 запросов в месяц хватает на проверку, но не на непрерывную запись. WS, по данным их блога, стоит $249/мес (Pro), что больше бюджета. Решение — по таблице §6 (`docs/data_sources.md` §7).
- **Данные о кортах** для условия «предыдущий матч на том же корте» нет ни в Sports WS, ни в OddsPapi (по известным полям). До их появления — консервативная замена: любой завершившийся матч того же турнира (`docs/architecture.md` §6).
- **Юрисдикция оператора.** Geoblock с VPS проверяет только IP сервера. Статус вашей страны (Латвия или Армения) — по официальному списку help.polymarket.com.
