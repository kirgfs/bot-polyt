# CLAUDE.md — hl_scout (скаут кошельков Hyperliquid для copy-бота)

Отдельный проект внутри репозитория. С Polymarket-ботом код не делит. ТЗ пользователя — сообщения в чате: разделы 1–8, 2.5 и 13.

## Что это
- Скаут **не торгует, не копирует и не шлёт сигналы по сделкам**.
- Выход — три типа сообщений в Telegram: СЛЕДИТЬ, ВНИМАНИЕ, ПРЕКРАТИТЬ/ЗАМЕНИТЬ. Плюс «НАСТРОЙКИ» после paper-теста (раздел 13).
- Депозит пользователя в стороннем copy-боте — $50.
- Цель $1000 за 30 дней — только вероятность. Параметры под неё не подгоняются.

## Статус
- Этап 1 готов: discovery, фильтры, score, копируемость, walk-forward, Monte Carlo, отчёт. Офлайн-тесты зелёные.
- **Этап 2 не начинать**, пока пользователь не увидит реальный отчёт по топ-10. Это его явное требование к порядку работ. Этап 2: Telegram на aiogram 3, monitor, paper 14 дней, НАСТРОЙКИ.
- С 2026-09-26 облачное окружение видит `api.hyperliquid.xyz`, `stats-data.hyperliquid.xyz` и `hyperliquid.gitbook.io` (добавлены в allowlist). `api.telegram.org` закрыт (egress 403).
- Строка мастер-аккаунта в лидерборде суммирует его субаккаунты, а их самих в лидерборде нет. Discovery разворачивает таких мастеров через `subAccounts` (api_notes §6).

## Жёсткие правила
1. Только публичный Info API и WebSocket. Никаких приватных ключей, никаких ордеров.
2. **Никаких фактов об API «по памяти».** Сначала пункт в `docs/api_notes.md` с источником и меткой доверия, потом код. Неподтверждённое сверяется командой `python -m hl_scout selfcheck`.
3. **Семантика copy-бота — только из его документации**, фиксируется в `copybot_fields.yaml`. Пока там `unverified`, сообщение «НАСТРОЙКИ» не выдаётся (fail-closed). Бэктест и paper обязаны моделировать именно эту семантику.
4. Без look-ahead. Всё, что применяется к тестовому окну, считается по данным до него. Прогноз строится только на out-of-sample днях.
5. Пороги живут в `config.yaml`, в коде их нет.
6. Секреты (токен Telegram) — только в `.env`. Логи маскируют секреты.

## Стек и команды
- Python 3.11+, Windows (без uvloop), asyncio, httpx, websockets, numpy, pydantic v2, structlog, SQLite (WAL).
- Установка: `pip install -e ".[dev]"`.
- Проверки: `pytest`, `ruff check src tests`, `ruff format src tests`.
- Запуск: `python -m hl_scout selfcheck | discover | report [--top 10] [--skip-discovery] | check <адрес> | account [<адрес>]`.

## Подключение к Hyperliquid (выводы из разбора трёх ботов, api_notes §10)
- Код сторонних ботов не копировать: в их репозиториях нет файлов LICENSE. Только идеи, реализованные заново.
- Перед сетевой работой — `InfoClient.preflight()`. Посреди запуска — автомат по `api.max_consecutive_failures`. Никаких часовых ретраев при мёртвой сети.
- WebSocket только через `WsSession`:
  - ping 30 с, pong 10 с;
  - повторная подписка и `on_reconnect` для дочитки пропуска через REST;
  - не больше 10 адресов в пользовательских подписках;
  - первый кадр `userFills` — снимок (`isSnapshot`).
- Адрес от пользователя — через `accounts.resolve_address` (агент → мастер).
