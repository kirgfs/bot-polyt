# hl_scout: методика

Как считаются фильтры, score, бэктест копирования и прогноз. Здесь же — что сознательно упрощено и где остаётся смещение. Факты об API — в [`api_notes.md`](api_notes.md).

## 1. Данные

| Что | Откуда | Зачем |
|---|---|---|
| Кандидаты | неофициальный лидерборд (окна week/month/allTime) + адреса из крупных сделок (WS `trades`, поле `users`) + ручные адреса | пул |
| Сделки | `userFillsByTime`, 180 дней (не больше 10 000 последних филлов) | действия трейдера, сделки, стиль |
| Капитал | `portfolio`: `accountValueHistory` + `pnlHistory` (окна allTime/month/week/day сшиваются, мелкие окна точнее) | доходности, просадки, месяцы |
| Позиции сейчас | `clearinghouseState`, `spotClearinghouseState` | ликвидация, хеджи со спотом |
| Движения денег | `userNonFundingLedgerUpdates` | выводы, общие источники переводов |
| Роль | `userRole` | vault / субаккаунт |
| Цены | `candleSnapshot` 1h / 15m / 1m (по 5000 последних свечей) | вход с задержкой, MAE, ликвидации, режим рынка |
| Funding | `fundingHistory` по монете, почасово | стоимость удержания моей копии |

Доходность аккаунта считается как ΔPnL / капитал на начало шага. Депозиты и выводы меняют капитал, но не PnL, поэтому доходностью не считаются (time-weighted return).

## 2. Жёсткие фильтры (провал любого = исключение)

Все считаются «на дату T» только по данным до T: и для текущей рекомендации, и для каждой точки walk-forward.

| Фильтр | Правило (config.yaml → `filters`) | Тип |
|---|---|---|
| История | `portfolio` покрывает 90 дней; филлы не обрезаны лимитом 10 000 внутри окна; сейчас: объём филлов за 30 дн ≥ 80% `perpMonth.vlm` | данные |
| Сделок за 90 дней | ≥ 50 закрытых сделок (round trip: из нуля в ноль; переворот закрывает одну и открывает другую) | стиль |
| Активность | последняя сделка ≤ 7 дней назад | стиль |
| Удержание | среднее > 15 мин | стиль |
| Max drawdown | < 30% по time-weighted индексу за 90 дней | **результат** |
| Прибыльные месяцы | ≥ 2 из 3 последних 30-дневных блоков | **результат** |
| Топ-3 сделки | < 50% всей прибыли за 90 дней | **результат** |
| Мартингейл | доливка при цене хуже средней входа на ≥ 1% = «усреднение убытка»; такие сделки ≤ 15%, не больше 2 доливок в сделке, без нарастающих доливок | стиль |
| Ликвидации | собственных ликвидаций за 90 дней — 0 | стиль |
| Далеко от ликвидации | сейчас: min расстояния mark → `liquidationPx` ≥ 10%; на истории: оценка (equity − MM) / gross notional | стиль |
| Equity | $2k–$200k (капитал всего аккаунта) | стиль |
| Одновременные позиции | медиана (по времени в рынке) ≤ 3 | стиль |
| Монеты | 1–5 «основных» (≥ 5% сделок) | стиль |
| Не vault | `userRole` = user или subAccount | стиль |
| Не маркет-мейкер | не (мейкер ≥ 80% объёма и ≥ 100 филлов в день) | стиль |
| Не ликвидационный бот | < 20% филлов — контрагент чужих ликвидаций | стиль |
| Не хедж / delta-neutral | противоположные позиции сопоставимого размера < 30% времени; funding < 40% PnL; спот в том же активе против шорта perp < 30% | стиль |
| Не дубль | связанные кошельки (синхронные сделки в пределах 30 с у ≥ 50% действий, прямые переводы, общий источник переводов, субаккаунт) — один трейдер; остаётся лучший по score | стиль |

Фильтры «по результату» — это выбор по прошлой доходности. Поэтому они учитываются как множественное тестирование в §3.

## 3. Score: навык, а не удача

`score = 100 · (0.30·skill + 0.25·stability + 0.30·copyability + 0.15·drawdown) − штрафы` (веса — `score.weights`).

- **skill** — Deflated Sharpe Ratio (Bailey & López de Prado): вероятность, что настоящий Sharpe выше ожидаемого максимума среди N случайных попыток. SR* = √V[SR] · ((1−γ)·Φ⁻¹(1−1/N) + γ·Φ⁻¹(1−1/(N·e))), учтены асимметрия и эксцесс дневных доходностей. «Попытки» — кошельки, прошедшие все фильтры **кроме** фильтров по результату; связанные кошельки считаются один раз. Дополнительно в отчёте — bootstrap p-value (блочный, H0: средняя доходность ≤ 0) с поправкой Бенджамини–Хохберга (q-value).
- **stability** — среднее из: доли недель в плюс; недельного mean/std; Sortino/5; (PF−1)/2 (всё обрезано до [0, 1]).
- **copyability** — PnL моей копии / PnL идеальной копии (без задержки, издержек и минимума $10) при тех же настройках на последнем окне. Сначала оценивается быстро, потом уточняется walk-forward.
- **drawdown** — 1 − MDD/30%.
- **Штрафы:**
  - частые мелкие доливки (< 25% позиции) — их убивает минимум $10;
  - недельная доходность на 2.5σ выше собственной истории (или без истории). Топ недельного лидерборда — антисигнал;
  - аккаунт моложе 120 дней.

Рекомендовать можно только при DSR ≥ 0.5 (`recommend.min_dsr`).

## 4. Симуляция моей копии

Модель стороннего бота описана в `copybot_fields.yaml` (семантика пока не подтверждена документацией бота):
- мой ордер = Copy Ratio × ордер трейдера;
- меньше $10 — Skip или Buy (округление до $10);
- Max Trade Size, Buy Times Per Token, Max number of tokens, Max Token Size / Margin, Max Total Margin;
- фиксированное плечо, Price SL/TP, Balance SL;
- полное закрытие, когда трейдер вышел в ноль;
- частичное закрытие — Copy Ratio × размер;
- если вход был пропущен, доливка трейдера открывает мою позицию («поздний вход»).

**Исполнение:**
- **Время:** действие трейдера (склеенные филлы одного ордера) исполняется через `delay` секунд. Основной расчёт — при 30 с (худшее из 10–30).
- **Цена:** VWAP трейдера, сдвинутый движением рынка за время задержки (линейная интерполяция внутри самой мелкой доступной свечи).
- **Издержки против меня:**
  - проскальзывание по ликвидности монеты (2–20 б.п.);
  - комиссия тейкера 4.5 б.п.;
  - комиссия бота (пока допущение 10 б.п.);
  - если свеча грубее 1 минуты — штраф `k·σ·√delay` (k = 0.5): движение внутри задержки не видно.

**Между действиями:**
- Позиции постоянны. Свечи сканируются векторно: худшая цена бара для ликвидации и стопов.
- В баре входа учитывается только часть после входа, чтобы на часовых свечах не ловить «ложную» просадку до входа.
- Funding списывается каждый час по ставке монеты.
- **Ликвидация:**
  - cross — equity ≤ суммы MM, где MM = notional / (2 · maxLeverage); счёт обнуляется (консервативно: backstop забирает MM);
  - isolated — теряется маржа позиции.
- **Balance SL** — выход, когда equity касается уровня; если equity уже ниже уровня (разрыв после события), выход по фактической.
- **Price SL** — выход по уровню минус проскальзывание стопа.

**Идеальная копия** — та же логика без задержки, издержек, минимума и лимитов. Относительно неё считается копируемость.

## 5. Walk-forward

- Окна: обучение 60 дней (отбор настроек), тест 14 дней, шаг 14 дней, скольжение по всей истории (до 180 дней). Перед каждым тестом нужно ≥ 90 дней истории для фильтров.
- **На обучающем окне:**
  1. Строится сетка настроек бота:
     - цель позиции $12–120 → Copy Ratio = цель / медиана notional позиции трейдера, округление вниз до 2 значащих цифр;
     - плечи: только те, где моя дистанция до ликвидации (1/L − MM) ≥ 1.5 × p95 MAE трейдера;
     - число позиций: p95 одновременных × маржа ≤ 80% депозита, иначе меньшая цель;
     - Buy Times, Skip/Buy, Price SL по MAE;
     - отключение системно убыточной стороны.
  2. Каждая настройка симулируется. Monte Carlo (2000 путей) её дневных доходностей даёт медиану и риски.
  3. Профиль выбирает настройку с максимальной медианой при своих рамках:

     | Профиль | P(обнуление) | P(потеря > 40%) | Плечо | Экспозиция |
     |---|---|---|---|---|
     | консервативный | ≤ 2% | ≤ 10% | ≤ 3x | ≤ 1× депозита |
     | средний | ≤ 5% | ≤ 20% | ≤ 5x | ≤ 2× |
     | агрессивный | ≤ 10% | ≤ 35% | ≤ 10x | ≤ 4× |

     Дополнительно для всех: ≤ 20% потерянных действий, стоп не выбивает зря > 30%, ожидаемый рост > 0.
  4. Пороги правил ПРЕКРАТИТЬ подбираются по сетке: копия −15/20/30%; просадка кошелька за 7 дней > 1.25/1.5/2 × нормы; 4/5/7 убыточных подряд. Критерий — лучший итог обучающего окна с правилами; при равенстве — значения по умолчанию.
  5. ПАУЗА в экстремальном режиме (24-часовая волатильность BTC выше расширяющегося 95-го перцентиля) включается, если на обучающем окне копия в таких периодах теряла.
- **На тестовом окне:**
  - симуляция с выбранными настройками;
  - правила считаются с нормой из обучающего окна;
  - при первом ПРЕКРАТИТЬ копия отключается через `human_reaction_min` (60 мин) — я реагирую на сообщение не мгновенно.
- **Требования к кошельку:** прибыльны ≥ 60% тестовых окон с копированием, окон ≥ 4, P(обнуление) < 10% хотя бы в одном профиле, проверки копируемости пройдены (§ 2.5 ТЗ: `replicability.py`).

## 6. Survivorship bias и look-ahead

- **Look-ahead.** Всё, что применяется к тестовому окну (фильтры, score, настройки, пороги правил, решение о паузе), считается по данным до его начала. Monte Carlo для прогноза берёт только тестовые (out-of-sample) дни.
- **Выбор кошелька.** Текущий топ выбран по сегодняшним данным, и его walk-forward оптимистичен. Поэтому отдельно считается **walk-forward всего процесса**: на каждую дату теста кошелёк выбирается заново из всего пула по данным до этой даты и копируется следующие 14 дней. Это главная честная оценка «что даст следование скауту».
- **Survivorship.** Пул набирается по объёму торгов, а не по прибыли: в него попадают и те, кто потом слил. Остаточное смещение — неизвестные правила попадания в неофициальный лидерборд (если «умершие» аккаунты оттуда пропадают, они не попадут и в пул).

## 7. Правила ВНИМАНИЕ / ПРЕКРАТИТЬ (`rules.py`, те же в бэктесте и в monitor)

| Правило | ПРЕКРАТИТЬ | ВНИМАНИЕ |
|---|---|---|
| Моя симулированная копия | −20% от выделенной суммы (подбирается) | 65% пути |
| Просадка кошелька за 7 дней | > k × p90 его 7-дневных просадок на обучающем окне (k подбирается), не меньше 5% | 65% порога |
| Стиль: плечо, размер позиций, частота | рост ≥ 2× к норме (по 7 дням, ≥ 5 сделок) | ≥ 1.65× |
| Новые монеты | ≥ 50% объёма за 7 дней | любая новая монета |
| Усреднение убыточной позиции | любое | — |
| Хеджи | противоположные позиции ≥ 30% времени за 7 дней (и выше двойной нормы) | 65% порога |
| Серия убыточных сделок | N подряд (подбирается) | ⌈0.65·N⌉ |
| Близко к ликвидации | < 5% | < 7.7% |
| Неактивность | 5 дней | 3.25 дня |
| Вывод equity | ≥ 30% за 7 дней | ≥ 19.5% |
| Экстремальный режим рынка | ПАУЗА (не отписка), если бэктест показал убыток копии в таком режиме | — |

## 8. Monte Carlo

- Блочный бутстрап (блок 3 дня) дневных доходностей копии из тестовых окон, 10 000 путей на 30 дней от $50.
- После касания Balance SL путь замораживается: бот выключен.
- **Выход:**
  - медиана и 5–95 перцентили капитала;
  - P(≥ $100), P(≥ $1000);
  - P(потеря > 40%);
  - P(обнуление) — капитал хоть раз < $5.
- Если дней в выборке < 28, в отчёте стоит пометка «мало данных».
- Цель $1000 нигде не участвует в выборе настроек.

## 9. Известные упрощения

- Для старой истории цены внутри часа неизвестны: вход с задержкой по часовой свече — интерполяция плюс штраф волатильности.
- Историческое плечо трейдера неизвестно. В бэктесте всегда фиксированное плечо (Follow Leverage не моделируется).
- Лимитные ордера бота (Limit Buy at Lower Price и т. п.) и Copy Limit Order не моделируются. Их настройка — по данным paper-теста.
- Сложный процент между тестовыми окнами не переносится: каждое окно начинается с выделенной суммы, а капитал складывается в Monte Carlo.
